# Telegram-аналитик Ozon и Wildberries

Бот на **Python 3.13.3**, **aiogram**, **Polars**, **SQLite** и **Claude** для магазинов **Ozon** и **Wildberries**. Работает через long polling: веб-сервер, сайт и webhook не нужны. Пользователь выбирает маркетплейс и подключает свой магазин в личном чате, затем выбирает отчёты кнопками. Один общий ключ Claude для обоих маркетплейсов задаёт владелец бота. Для локального тестирования база хранится в обычном файле; устанавливать PostgreSQL или Docker не нужно.

## Запуск в PyCharm

Нужны [Python 3.13.3](https://www.python.org/downloads/release/python-3133/), PyCharm и токен Telegram-бота, созданного через [BotFather](https://t.me/BotFather). Инструкции подходят для Windows, macOS и Linux.

1. Скачайте или клонируйте репозиторий и откройте его папку в PyCharm через **Open**.
2. В **Settings → Project → Python Interpreter** выберите **Add Interpreter → Add Local Interpreter → Virtualenv**. Создайте окружение `.venv` в папке проекта, выбрав установленный Python **3.13.3**.
3. В терминале PyCharm установите зависимости в это окружение:

```bash
python -m pip install --require-hashes -r requirements.lock
```

4. Скопируйте файл `.env.example` в той же папке и назовите копию **`.env`**. Заполните его:

```dotenv
TELEGRAM_BOT_TOKEN=ваш_токен_от_BotFather
DB_PATH=data/ozon_bot.sqlite3
CLAUDE_API_KEY=ваш_общий_ключ_Anthropic
CLAUDE_MODEL=claude-sonnet-4-6
CLAUDE_MAX_TOKENS=4096
CLAUDE_THINKING_MODE=disabled
SESSION_TTL_MINUTES=60
```

5. Откройте [run_bot.py](run_bot.py), нажмите правой кнопкой мыши и выберите **Run 'run_bot'**. Если создаёте конфигурацию вручную, задайте **Script path** = `run_bot.py`, **Python interpreter** = `.venv`, **Working directory** = папка проекта.

Запуск из терминала с активным окружением равнозначен:

```bash
python run_bot.py
```

Файл `run_bot.py` сам подключает код из `src`, поэтому отмечать `src` как Sources Root или отдельно устанавливать проект не требуется. Если терминал использует другой Python, активируйте окружение `.venv` в настройках терминала PyCharm или запускайте через кнопку Run с выбранным интерпретатором.

Бот автоматически создаст каталог `data`, файл `ozon_bot.sqlite3` и свои таблицы при первом запуске. `DB_PATH` можно оставить по умолчанию; относительный путь считается от папки проекта. Файл `.env` также читается из папки проекта. Файл базы и локальные настройки исключены из Git. Остановить бота можно кнопкой Stop в PyCharm или `Ctrl+C` в терминале; после перезапуска пользователи входят заново.

Запускайте один экземпляр на один файл базы: второй процесс отклоняется файловой блокировкой. Нужен доступ к `api.telegram.org` и `api.anthropic.com`; для Ozon — к `api-seller.ozon.ru` и `api-performance.ozon.ru`, для Wildberries — к API-доменам из раздела подключения ниже.

Вместо `CLAUDE_API_KEY` в `.env` можно вставить **один** ключ в константу `CLAUDE_API_KEY` в [config.py](src/ozon_bot/config.py). Значение из окружения имеет приоритет. Не добавляйте настоящий ключ в Git; `.env` уже исключён через `.gitignore`. Без ключа Claude остальные отчёты работают.

В облачной среде Telegram-транспорт учитывает `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY`. Дополнительное доверенное хранилище сертификатов задаётся через `SSL_CERT_FILE`/`SSL_CERT_DIR`; проверка сертификатов остаётся включённой.

### Альтернатива с uv

Если используете [uv](https://docs.astral.sh/uv/getting-started/installation/), он сам установит Python и создаст окружение:

```bash
uv python install 3.13.3
uv sync --frozen --extra dev
uv run --frozen python run_bot.py
```

Перед запуском заполните `.env`, как описано выше. Команда `uv run --frozen ozon-bot` тоже поддерживается.

## Вход и меню

1. Откройте личный чат с ботом и отправьте `/start`.
2. Выберите кнопкой **Ozon** или **Wildberries** и введите имя.
3. Для Ozon введите **Client-Id** и **Api-Key Seller API**; для Wildberries — **API-токен**. Client-Id для Wildberries не нужен. Создавайте ключи с доступом только к нужным разделам.
4. Бот проверит доступ к магазину и откроет меню: «Финансы», «Продажи», «Реклама», «SEO», «Конкуренты», «Остатки», «Категории», «Совет ИИ».

Через кнопки также доступны «Период», «Общая прибыль», «Налоги и CSV», «Подключить рекламу», «Обновить данные» и «Завершить». Имя, реквизиты подключения, произвольные даты и ставка вводятся текстом; CSV отправляется файлом. Разделы и действия выбираются кнопками. `/help` показывает краткую справку.

Периоды: последние 7, 30 или 90 дней, текущий месяц либо две даты `ГГГГ-ММ-ДД ГГГГ-ММ-ДД`, включая обе границы. Исходно выбраны 30 дней. Границы запросов Ozon задаются в UTC. Финансовый API Ozon доступен с 1 января 2022 года; бот допускает периоды до 10 лет, но фактическая доступность истории зависит от выбранного API. Данные магазина кешируются на 5 минут; «Обновить данные» запрашивает их заново.

«Общая прибыль» запрашивает дату первой продажи и строит финансовый отчёт от неё до сегодняшнего дня. Результат ограничен доступной историей API и полнотой себестоимости; это не гарантия получения всей истории магазина. Для больших магазинов начинайте с короткого периода. При достижении пределов загрузки бот выводит предупреждение о неполноте.

### Доступ Wildberries

Основной токен используется для разных категорий API:

| Категория доступа токена WB | Для чего нужна | Домен |
| --- | --- | --- |
| Статистика | Заказы, продажи и возвраты | `statistics-api.wildberries.ru` |
| Финансы | Детализация реализации для финансового отчёта | `finance-api.wildberries.ru` |
| Аналитика | Отчёт об остатках на складах | `seller-analytics-api.wildberries.ru` |
| Контент | Карточки, названия, описания и категории товаров | `content-api.wildberries.ru` |

Недостаточные права или недоступный источник показываются предупреждением. Отсутствие данных не означает нулевые продажи или прибыль. Statistics API хранит ограниченную историю заказов и продаж — ориентируйтесь на последние 90 дней; запрос более раннего периода не восстанавливает потерянную историю. Финансовая история проверяется отдельно по доступности отчёта. Для рекламы подключается отдельный токен категории «Продвижение», как описано ниже.

### Как понимать суммы и статусы

Все денежные показатели — в рублях. Финансовый итог опирается на начисления Ozon или детализацию реализации WB: комиссия и логистика не вычитаются из уже итоговой суммы повторно. Прибыль = итог операций маркетплейса − себестоимость − оценка налога. Внешние расходы магазина не включены; рекламный отчёт не вычитается второй раз из финансового итога.

Для WB используется действующий финансовый API: `POST /api/finance/v1/sales-reports/detailed`, детализация по дням реализации `rrDate`. Суммы продаж и возвратов имеют разные знаки; комиссия показывается по доступным полям отчёта, без НДС. Финансовая сумма к выплате не равна обороту заказов. Если экономические поля отсутствуют, валюта не RUB или неоднозначные корректировки не позволяют корректно свести отчёт, бот предупреждает об этом и не выдаёт прибыль как точное число.

В «Налоги и CSV» выберите ставку 0%, 6%, 15% либо введите другую от 0 до 100%. Это **процент от положительной выручки после возвратов**, а не полноценный налоговый учёт. Кнопка 15% также применяет процент к выручке; она не рассчитывает УСН «доходы минус расходы». НДС, взносы, льготы и особенности режима не учтены. До выбора ставки используется 6% с предупреждением.

Себестоимость задаётся за одну единицу товара. Если её нет для части проданных SKU, точная прибыль недоступна. Если API не передал количество позиции и его нельзя сопоставить с отправлением, бот может показать явно обозначенную оценку при 1 шт. на позицию. При неполных денежных полях итог также помечается неполным. Восстановление себестоимости при возврате не учитывает брак и утилизацию.

**Ozon:** заказ в отчётах продаж — **отправление**, поэтому один покупательский заказ может дать несколько записей. Выкуп — текущий статус доставки у отправлений, **созданных** в период; это не число доставок по фактической дате получения. Отмены не считаются возвратами. Количество возвратов зависит от доступных финансовых операций и статусов и может быть оценочным. Средний чек — сумма товаров в выкупленных отправлениях, делённая на число таких отправлений.

**Wildberries:** заказы и отмены учитываются по дате заказа, выкупы и возвраты — по дате соответствующего события Statistics API. Поэтому выкупы в периоде могут относиться к более ранним заказам. Средняя цена выкупленного товара не является средним чеком покупательской корзины. При недоступной истории выкупов или возвратов они помечаются недоступными, а не нулевыми.

Оборот категории — стоимость созданных заказов, включая отменённые. Он не показывает стоимость складских запасов или финансовую выручку после удержаний. В Ozon отправление с товарами разных категорий учитывается в каждой из них. Для WB отдельно показываются оборот заказов, выкупов и выкупов после возвратов; эти суммы относятся к разным событиям и не должны совпадать.

Названия категорий загружаются из справочника Ozon или карточек WB. При недоступности справочника Ozon показываются идентификаторы с предупреждением; отсутствующие категории попадают в «Без категории».

Дни покрытия остатка — текущий доступный остаток / среднее число проданных единиц в день выбранного периода. Для Ozon спрос оценивается по выкупленным единицам; для WB — по выкупам за вычетом возвратов, не ниже нуля. Дефицит: менее 14 дней; излишек: более 60 дней либо нет наблюдаемого спроса при полном источнике продаж. Поставка рассчитана до 30 дней покрытия. При неполных данных продаж WB рекомендации дефицита, излишка и поставки не рассчитываются.

Остатки WB получаются из `warehouse_remains` только для складов Wildberries. Остатки на складах продавца FBS, товары в пути и резерв этим источником не покрываются. Доступный остаток не уменьшается повторно на товары в пути. Оценка покрытия — ориентир без сезонности, срока поставки и будущих поступлений, а не гарантированный прогноз.

ДРР = рекламные расходы / атрибутированная выручка × 100%; ROAS = атрибутированная выручка / расходы. При нулевой выручке ДРР не определён. Рекламную выручку нельзя прибавлять к финансовой выручке. Порог «расходы ≥ выручки» выделяет товар для проверки; фактическая убыточность дополнительно зависит от маржи, комиссии, логистики и налогов.

## Подключение рекламы

Нажмите «Подключить рекламу». Бот запросит реквизиты выбранного маркетплейса:

- **Ozon:** **Client ID** и **Client Secret Ozon Performance API**, отдельные от Seller Client-Id/Api-Key.
- **Wildberries:** один **API-токен категории «Продвижение»** для `advert-api.wildberries.ru`; Client ID и Client Secret не нужны. Для длительной работы предпочтителен персональный или сервисный токен: у базового токена более строгие лимиты запросов.

При выборе «Реклама» или «Совет ИИ» бот загрузит статистику; ожидание зависит от API и лимитов. Для WB запросы разбиваются на интервалы до 31 дня и группы до 50 кампаний, включая завершённые, активные и приостановленные кампании. Доступность более старой статистики зависит от WB. Если достигнут предел загрузки или API не вернул полную разбивку по товарам, отчёт помечается неполным; доступный общий расход сохраняется. Рекламные заказы и атрибутированная выручка WB не означают фактические выкупы и прибыль. Отключение доступно в «Налоги и CSV».

Если реквизитов нет, загрузите CSV рекламы. Импорт рекламы переключает источник на CSV и отключает рекламное API-подключение с удалением его ключа из памяти. Повторное подключение рекламы переключает источник обратно на API и заменяет статистику в памяти после загрузки. Не смешивайте в файле итоги кампании с её построчной разбивкой по товарам: это удвоит суммы.

## Импорт CSV

«Налоги и CSV» → нужный раздел. Бот отправит шаблон; замените демонстрационные строки своими и загрузите документ. Такие же примеры лежат в [examples](examples). Новая загрузка **заменяет** прежнюю для выбранного раздела в текущем сеансе. Шаблоны автоматически в анализ не включаются.

Поддерживаются UTF-8/UTF-8 BOM и Windows-1251, разделитель `;` или `,`, даты `YYYY-MM-DD` либо `ДД.ММ.ГГГГ`. Размер — до 2 МиБ, до 20 000 строк. Числа неотрицательные, рейтинг 0–5, позиции — целые от 1. Идентификаторы сохраняются текстом, включая ведущие нули; при редактировании в Excel задавайте им текстовый формат. Не добавляйте столбцы с API-ключами или другие поля вне шаблона.

| Файл | Обязательные столбцы | Дополнительные столбцы |
| --- | --- | --- |
| [costs.csv](examples/costs.csv) | `sku`, `cost` | — |
| [ads.csv](examples/ads.csv) | `date`, `campaign_id`, `campaign_name`, `spend`, `revenue`, `orders` | `sku`, `clicks`, `impressions` |
| [seo.csv](examples/seo.csv) | `sku`, `title` | `description`, `keywords`, `position`, `previous_position`, `date` |
| [competitors.csv](examples/competitors.csv) | `date`, `competitor_sku`, `name`, `price` | `sku`, `category`, `rating`, `reviews`, `position` |

Для **Ozon** в себестоимости `sku` должен соответствовать идентификатору товара магазина; сопоставление также поддерживает артикул `offer_id` и ID товара из каталога. Для **WB** используйте **nmID** — артикул Wildberries, а не штрихкод — в столбце `sku` себестоимости, рекламы, SEO и привязки своего товара в конкурентах. В конкурентах необязательный `sku` связывает наблюдение с вашим товаром. `reviews` — число отзывов, не их тексты. Несколько дат для одного конкурента позволяют сравнить позиции. В SEO `previous_position` — предыдущая позиция для сравнения; положительное изменение означает подъём. Сравнивайте позиции для одного запроса, региона и одинаковых условий поиска.

Подключённые API не дают полного рынка конкурентов и сопоставимых поисковых позиций по всем запросам. Для этих функций в обоих маркетплейсах используйте CSV из собственных выгрузок или законно доступного источника внешней аналитики. Бот не собирает чужие карточки скрейпингом и не выдумывает отсутствующие позиции. Проверки названий — формальные подсказки, не обещание роста в поиске; описание или изображение, отсутствующее в ответе API, не означает пустую карточку. В Ozon для каталогов до 200 товаров бот дополнительно запрашивает доступные описания; при большем каталоге используйте CSV содержания карточек. В WB доступные поля карточек загружаются через Content API.

## Сеансы и ключи

Ключи Ozon Seller/Performance, основной токен WB и токен WB «Продвижение» хранятся только в памяти процесса на время сеанса. Они не записываются в SQLite или `.env` и не передаются Claude. SQLite содержит метаданные сеанса — имя, ID пользователя/чата, время окончания, ставку налога — и проверенные CSV-импорты.

«Завершить», истечение срока бездействия и перезапуск очищают ключи и завершают сеанс. По умолчанию срок — 60 минут после последнего обращения; `SESSION_TTL_MINUTES` допускает 5–1440 минут. С завершением удаляются записи сеанса и связанные импорты; при запуске очищаются данные предыдущих сеансов, ключи которых уже потеряны. Логическое удаление записей не гарантирует уничтожение всех следов в файле базы, его резервных копиях или на стороне Telegram. Не публикуйте файл базы.

Бот пытается удалить сообщения с ключами из чата, но Telegram может отказать. Вводите их только в личном чате и учитывайте, что сообщения проходят через Telegram; удаление сообщения не гарантирует отсутствие серверных копий. Не публикуйте ключи и не включайте отладочный вывод HTTP-заголовков.

Нажатие «Совет ИИ» отправляет сводные бизнес-показатели, часть названий и замечания в Anthropic. Ключи магазина в запрос не входят. Все пользователи используют общий ключ владельца: запросы расходуют его баланс. Рекомендации и прогнозы Claude нужно проверять по фактическим данным.

## Claude: ответы, настройки и повторные запросы

`CLAUDE_MODEL` задаёт модель, доступную вашему аккаунту Anthropic. `CLAUDE_MAX_TOKENS=4096` ограничивает число выходных токенов (допустимо 256–16384), а `CLAUDE_THINKING_MODE=disabled` явно отключает режим размышлений. Если выбранная модель не принимает явное отключение, задайте `CLAUDE_THINKING_MODE=auto`: тогда бот не отправляет параметр `thinking`, и поведение определяет модель. При таком режиме внутренние размышления могут расходовать лимит выходных токенов. Само по себе успешное HTTP-соединение не гарантирует наличие видимого текста в ответе.

Бот собирает видимый текст из всех текстовых блоков ответа. Если текста нет, сообщение различает исчерпание лимита токенов, отказ модели, незавершённый ответ и ответ только с внутренними блоками. Точную причину ранее полученного общего сообщения «Claude вернул пустой ответ» без метаданных того запроса установить нельзя. В журнал попадают только технические признаки: причина остановки, типы блоков, счётчики токенов и безопасный ID запроса. Содержимое запроса, ответа, ключи и внутренние размышления не записываются.

Пустой ответ, сетевая ошибка и ошибка сервера не запускают автоматический повтор платного запроса. Только ответ API `429` обрабатывается ограниченными повторами. Принятый Anthropic запрос может расходовать токены даже без видимого текста; новый запрос также может списать средства.

Успешный совет сохраняется в памяти до завершения текущего сеанса и повторно показывается для тех же данных. После ошибки бот в течение 60 секунд также не отправляет тот же запрос при обычном повторном нажатии «Совет ИИ». Кнопка «Новый запрос ИИ (платный)» принудительно создаёт новый запрос; после 60 секунд или изменения исходных данных обычное нажатие тоже может отправить новый запрос. Длинные ответы разбиваются на сообщения; при проблеме с доставкой бот пробует отправить уже полученный совет файлом `ai_advice.txt`. Если Telegram не принял и файл, ответ остаётся в памяти сеанса.

Кнопка «Последний ответ ИИ» повторно выдаёт последний успешно полученный совет без запросов к маркетплейсу, рекламе или Claude, даже после смены периода или ошибки нового платного запроса. Этот текст относится к данным и периоду прежнего запроса, а не к новому выбранному периоду.

В Claude отправляется компактная сводка: при большом объёме детализация сокращается и помечается как выборка. Это ограничивает размер запроса, но не заменяет полный анализ каждой карточки большого магазина.

## Проверка разработки

```bash
uv run --frozen --extra dev pytest -q
uv run --frozen --extra dev ruff check src tests
```

Тесты хранилища создают временные файлы SQLite автоматически. Отдельная база, сервер и `TEST_DATABASE_URL` не нужны; файл базы рабочего бота не используется. Для запуска тестов через PyCharm выберите интерпретатор окружения, подготовленного командой `uv sync --frozen --extra dev`.

Тесты API используют подставные HTTP-ответы; они проверяют расчёты, пагинацию и обработку ошибок, но не подтверждают доступ вашего магазина, состав его живых данных или доступность платных функций маркетплейса. Для полноценной проверки нужны настоящие токены Telegram, выбранного маркетплейса и Claude. Контракты API Ozon и WB могут меняться; отказы и неполные источники показываются в отчёте. Финансовые расчёты нужно сверять с реальными отчётами своего кабинета, особенно при корректировках и дополнительных удержаниях.

## Структура

- `run_bot.py` — простой запуск из PyCharm и терминала.
- `src/ozon_bot/main.py` — запуск long polling и завершение процесса.
- `bot.py`, `sessions.py` — кнопки, ввод, кеш и время жизни сеансов.
- `ozon.py`, `performance.py` — чтение API магазина и рекламы.
- `wildberries.py`, `wildberries_ads.py` — данные магазина и реклама Wildberries.
- `analytics.py` — расчёты Polars и пояснения к показателям.
- `imports.py`, `storage.py` — проверка CSV и SQLite без ключей магазинов.
- `ai.py`, `config.py` — общий Claude и настройки.
- `tests/` — расчёты, API на подставных ответах и интеграционные проверки SQLite.

Версия Python закреплена в `.python-version`, зависимости — в `uv.lock`. Команда `uv sync --frozen --extra dev` использует сохранённый lock-файл.

### Необязательный Docker

Для контейнера бота предусмотрен `Dockerfile` на Python 3.13.3. Для работы на компьютере через PyCharm контейнер не нужен. Зависимости контейнера устанавливаются из `requirements.lock` с проверкой хешей. При обновлении `uv.lock` обновляйте и экспорт:

```bash
uv export --frozen --no-dev --no-emit-project --format requirements-txt --output-file requirements.lock
docker build -t ozon-telegram-analyst .
```

Запуск с сохранением файла SQLite в отдельном Docker volume:

```bash
docker run --rm --env-file .env -e DB_PATH=/app/data/ozon_bot.sqlite3 -v ozon-bot-data:/app/data ozon-telegram-analyst
```

Если ваша среда использует корпоративный прокси и отдельный корневой сертификат, Dockerfile поддерживает BuildKit `--secret id=pip_ca,src=/path/to/ca-bundle.pem`; проверку TLS отключать не требуется.
